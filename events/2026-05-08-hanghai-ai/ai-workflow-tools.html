核心判断

这部分最有价值的不是工具名，而是“国外 harness + 国内 model + 本地知识库 + 结果回传”的工作法：把 AI 变成能读文件、改文件、复盘过程的执行同事。

现场原始信息

  • 便利贴里直接出现：Cloud Code + 国内 Model、OpenClaw/Cloud Code 等 Agent、行业专业知识库、朋友圈文案、视频号图文、海外内容本地化。
  • 林勇：非技术出身，自己装 Cloud Code，用 Honey 框架 + Minimax 国内模型；没有信用卡就先用国内模型，效果也还不错。
  • 具体用法：把项目文件上下文给 AI，描述 bug 或需求；AI 改完后把新结果/新 bug 回传，让它继续排查。
  • 复盘沉淀：用 Cloze 插件把“排查了什么、怎么解决、最后总结”整理成 Markdown，沉淀到 Obsidian。
  • 宋超：Cloud Code 本质是编程平台，但普通人可把它当“解决问题的方法”；CC switch 可切国内大模型，小米 MIMO 被认为好用，DC 更便宜。
  • 修东西：本地部署 OpenCloud/龙虾后，Cloud Code/Codex 能读取本地文件来修；宋超提到“Codex 修理一切”。
  • HTML PPT：把内容放 TXT/Word，要求生成 HTML 格式 PPT，再配 frontend design skill 做美观排版。
  • 直播文档知识库：300 多场直播，每场 2-3 万字，总量上千万字；让 Cloud Code 设计策略，导入 Obsidian、打标签、用 Ollama 做本地向量化，约十几二十分钟完成。
  • 检索效果：提问“关系内耗文章有哪些角度”，系统从过往直播中抓出 4-5 个贴近角度，并指出对应经历和直播内容。
  • 知识库结构：知乎、小红书、抖音内容分开；每个平台再分母话题、子话题、一级/二级/三级话题；调用时指定类别，省 token、效果更好。

可以怎么复制/跟进

  • 个人 IP 用法：直播/文章/课程语料 -> Obsidian -> 标签/向量化 -> 生成选题/大纲/PPT/朋友圈。
  • 公司用法：SOP、客户案例、话术、投放复盘、客服问答、产品文档统一放本地知识库。
  • Agent 协作法：给事实、给文件、给目标、让 AI 先给计划；执行后把结果回传；最后要求生成复盘笔记。
  • 不懂技术时的起步：先做番茄时钟、小工具、HTML PPT、文档整理这种低风险任务，理解它怎么工作。

判断、风险和边界

  • 知识库不是越大越好，核心是调度。每次全量读会烧 token，还容易输出泛泛内容。
  • 知识库能生成相似内容和选题，但真正创新仍需要人的判断、业务经验和额外 skill。
  • 国内模型并非不能用，关键是 harness 能不能读文件、调用工具、保存结果。
