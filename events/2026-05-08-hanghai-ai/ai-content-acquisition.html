核心判断

小红书自动化的关键不只是“AI 生成内容”，而是把人原来做内容和发布的 20 个流程，压缩成一个标准化流程；最终验收指标不是文案质量，而是有没有客资。

现场原始信息

  • 歪仔：小红书矩阵规模很大，几千账号量级；卡点是用 AI/龙虾批量控制账号后，抖音、小红书、视频号都会有违规/规则问题。
  • 瑾糖：自己只有五六个号，没遇到违规；判断可能是技术方案/环境差异。歪仔补充：他们一个手机、一个卡、一个网络也做了，仍然没用，规模不是一个概念。
  • 瑾糖的流程：先有模板库/爆款库/同行优质模板库，图片和文案都入库；AI 对接 API 写、改、做图；视频调用即梦等；最终生成内容。
  • 发布方案：不是网页发布，而是 ADB 或无障碍方案控制自己的手机发布，模拟真实操作路径。
  • 发布后：扫描 APP 内信息，把过去 SaaS 工具里的 20 个步骤串成一个流程。
  • 内容类型：副业粉，图文为主；出现过 10 万、20 万爆款。
  • 验收标准：不看“写得好不好”，只看能不能带来客资；能带来价值就是有用。
  • 找选题：歪仔早期会挖培训赛道主播语音/文案、分析 10 万赞以上内容；后来认为直接把视频文案丢给 AI，在同一个对话里反复聊即可，不一定要建知识库。
  • 素材数量：一两百条也可以，扒出来让 AI 改，循环 200 条，改了就发；关键是业务理解，不是 AI 理解。
  • 工具组合：Codex / Claude，豆包 API 做图片，脚本保存到指定文件夹，再按固定文案格式输出。

可以怎么复制/跟进

  • 第一步：定义客资动作，是私信、加微信、进群、下单还是表单。
  • 第二步：建立爆款库，字段至少包括标题、封面结构、开头钩子、正文框架、评论问题、转化路径。
  • 第三步：把人工流程写成 SOP：找素材 -> 改写 -> 做图/视频 -> 保存 -> 传手机 -> 发布 -> 扫描数据 -> 回收线索。
  • 第四步：用 Agent 找现成开源项目或拆 API，先跑小规模，再扩大。
  • 第五步：判断自动化是否有效，不看单篇审美，按线索成本、线索质量、封号率和复购来评估。

判断、风险和边界

  • 规模差异很重要：5 个号和几千个号不是同一个问题，前者关注提效，后者关注风控、环境、账号资产和平台识别。
  • AI 不能判断你也判断不了的事情，比如“这个爆文是不是投流了”。你能定义判断标准，AI 才能学。
  • 自动化不是代替业务理解。现场反复强调：你对业务不了解，AI 帮助很浅。
  • 同城获客的提问模板：我是某业务，目标半径 X 公里，套餐/单品价格 X，客单价 X，目标人群 X，想在小红书打爆某套餐，请帮我设计内容体系、账号策略和转化路径。
