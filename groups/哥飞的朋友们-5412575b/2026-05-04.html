qiayue:
简单来说，是这样的：
1、以前有两个页面，首页和 search 内页，首页是一个典型的落地页，实际无功能，大家主要用的是 search 内页；
2、后来他们团队决定，要把首页改成直接提供 search 服务，于是就用 search 内页替代了首页；
3、但这样就会出现重复页面了，首页打开的和search 内页打开的网页内容一模一样，在谷歌看来，就是重复页面；
4、为了防止出现重复页面，就需要通过 canonical 来告诉谷歌，到底哪个网址才是站长选定的规范化网址，由于 search 内页之前就存在，且谷歌已经在这个页面积累到了用户行为数据了，所以站长最终的决定是，把首页的canonical 也设置为 search 内页，而不是把 search 内页的 canonical 设置为首页；
5、设置好了 canonical ，只是告诉了搜索引擎，哪个网址是规范化的网址，但用户打开两个页面，依然会看到重复的网页，这时候，站长又做了一个操作，把 search 内页 307 到首页；
6、最终就成了现在的局面，用户行为数据依然在 search 内页这个网址上积累，外链权重也在这个网址积累，但用户实际打开网页看到的是首页。

qiayue:
他这样做，是为了让首页可以继承 search 内页的搜索排名和权重。

如果他当时直接把 search 内页 301 到首页，的确可以把 search 内页的外链权重慢慢转移到首页，但是首页毕竟是一个新页面，短时间是无法继承 search 内页的排名和权重的，也就是说，会导致丢排名，掉流量。

我们之前讲过，用户行为数据是绑定在具体网址上的，所以我们需要做精品工具页面，让拿排名的落地页跟实际提供功能的工具页是同一个页面。

所以他要做的，就是留下 search 内页的行为数据，于是把首页的 canonical 指向到 search 内页，而不是在 search 内页修改 canonical 指向到首页。

然后他这里还利用了谷歌爬虫的一个特性，当一个 url 会 30x 跳转到另一个 url 时，谷歌爬虫会去抓取目的地 url 的网页，来当做当前网页的内容。

这一点大家如果去观察一些短链域名在谷歌的搜索结果就能够发现。

在谷歌查看 consensus.app 的搜索结果，也一样可以看到，虽然 srarch 内页已经 307 到了首页，但是谷歌抓取收录拿排名的依然还是 search 内页，并且鼠标放上去看到的 url 也还是 search 内页的网址。

也就是说，谷歌本来要抓取的是 search 内页，结果因为跳转抓到了首页的 html ，而首页的 canonical 恰恰指向的就是 search 内页，于是搜索引擎就会认为，他抓到的，就是原先的 search 内页。

所以原先 search 内页的用户行为数据、权重、排名都保留下来了。
